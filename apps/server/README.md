# Luvia Server 候选

当前包提供 API 与 worker 双进程入口，并包含数据库、安全、查询、扫描和迁移模块的部分实现。完整接口和媒体管线尚未就绪，不能用于生产数据或接管 v1。

已实现账户偏好深度合并、壁纸令牌配置与随机浏览的直接目录和排除筛选。会话写请求使用 `X-Luvia-Request: 1`，Bearer 令牌请求不依赖该标头。

管理员可创建、查询和控制作业；`/api/v2/events` 提供作业与媒体库变化事件。worker 接入扫描、旧库导入、元数据、批量缩略图、媒体缓存、视频预览、HLS 转码、缓存淘汰和健康检查。

扫描会物化真实目录层级与计数，并按媒体库排除规则跳过系统目录。文件夹接口按用户权限过滤，并根据设置决定是否展示宿主机路径；Linux 挂载解析支持 `LUVIA_HOST_PATHS` 映射。

扫描成功后记录媒体库的最近扫描时间；读取异常时保留已有索引并标记不可用，重试已完成但含错误的扫描时重新检查目录。

管理员可管理媒体库、目录选择与站点设置。新挂载默认不会自动启用；启用自动发现后，worker 启动时会为候选挂载创建媒体库并排队扫描。间隔扫描由共享调度状态去重，仅为启用的媒体库排队。媒体数量估计由 worker 在前两层异步抽样。

管理员可管理用户和虚拟目录权限；重置密码会撤销该用户的会话，系统会保留至少一名管理员。

管理员概览展示媒体、缓存、作业和 API 运行指标。分钟曲线中尚无采样的时间点为 0；日志使用脱敏的结构化输出，worker 日志经有界的数据库中转进入 API 内存环形缓冲。

相册支持手动选择媒体或保存智能筛选条件，列表与封面按当前用户可访问的目录计算；智能相册的媒体查询同时应用保存的筛选条件和请求筛选条件。筛选候选、筛选后的时间分桶和相册汇总通过只读查询线程执行，线程数和等待队列有上限。

分享支持媒体、文件夹和相册目标，可设置密码、过期时间及原文件下载权限。访客资源访问检查分享状态、目标成员和所有者当前目录权限；禁用的媒体库不出现在媒体结果中。分享视频支持独立访客会话的 HLS 播放。

下载接口签发十分钟有效的一次性票据，使用 ZIP 存储模式流式打包；打包时逐项核验会话、目录权限和媒体真实路径。

扫描成功后会排队提取元数据：图片读取 EXIF、方向和 GPS，音视频通过 ffprobe 读取编码与时长；拍摄时间依次使用元数据、文件名和修改时间。元数据按批次续跑，文件租约防止多个 worker 重复处理。原文件及浏览器可解码图片提供 Range 和 ETag。图片及视频缩略图、ThumbHash、静音视频预览、需转换的显示版本及深度缩放瓦片由 worker 生成，缓存按访问时间淘汰。

缩略图就绪状态随源文件变化和缓存淘汰更新；生成与淘汰时同步调整受影响文件夹封面。

HEIC/HEIF 使用 FFmpeg 解码后生成显示图和缩略图；相机 RAW 格式尚未接入解码和扫描。

媒体详情返回提取到的 EXIF、位置、视频信息、目录面包屑和当前用户的手动相册，并检查目录访问权限。

回忆接口提供往年同日、最近加入与随机媒体；搜索联想覆盖可访问的文件夹、相册、相机型号和媒体。

旧版登录、列表、原文件、缩略图和目录入口支持基础兼容；列表支持旧版排序、筛选和种子分页，目录支持收藏、搜索和封面。壁纸令牌按其保存的内容与方向配置抽样。旧版用户自定义附加字段未迁移，搜索细节和真实旧客户端行为仍需验证。

使用 Node 24 运行当前测试和类型检查：

```sh
npx -y -p node@24 -- pnpm --filter @luvia/server test
npx -y -p node@24 -- pnpm --filter @luvia/server typecheck
npx -y -p node@24 -- pnpm --filter @luvia/server bench
```

基准默认生成一百万条合成媒体，并在独立进程持续扫描合成文件时测量默认读取路径；临时数据库在结束时删除。无筛选时间线使用物化月份统计，筛选查询与真实 NAS I/O 仍需另行测量。

生成本机联调素材（需要 FFmpeg，目标同名文件存在时拒绝覆盖）：

```sh
npx -y -p node@24 -- pnpm --filter @luvia/server fixtures --output /path/to/fixture
```

使用 Node 24 启动本地双进程：

```sh
DATA_DIR=./data CACHE_DIR=./cache MEDIA_ROOT=/path/to/fixture npx -y -p node@24 -- pnpm --filter @luvia/server dev
```

`/healthz` 检查 API 事件循环，`/readyz` 还要求 worker 心跳正常。worker 启动时探测 FFmpeg 和 NVENC 单帧编码能力；探测结果可从管理员系统接口读取。在 macOS 开发环境中，`MEDIA_ROOT` 指定本地合成媒体目录；Linux 环境以 mountinfo 中检测到的候选挂载限制扫描范围。

多个 worker 通过共享数据库中的租约限制 FFmpeg 和缩略图并发，长视频转码期间仍可处理其他作业。HLS 按访问会话隔离，分片生成后即可播放；30 秒无访问时停止转码，闲置 60 秒后回收会话缓存。活跃播放的分片暂不参与缓存淘汰。支持探测 NVENC 并在不可用时回退 CPU；其他硬件编码路径尚未验证。缩略图请求断开后取消后台作业的完整链路尚未实现。

现有测试使用临时合成数据，不代表大媒体库性能、真实旧库迁移或生产环境验收。作业领取与扫描锁支持租约，扫描支持目录级断点。旧版导入只迁移用户数据并保留待匹配收藏；完整生产迁移、媒体管线与端到端性能尚未验收。

根目录的 Dockerfile 和 Compose 配置使用同一 Node 24 镜像运行 API 与 worker，媒体挂载为只读；可按 Compose 注释启用 NVIDIA 设备。容器构建、卷权限、GPU 与前端资源尚需在 FNOS 验证，当前后端仍不可用于生产。

存在 `apps/web/dist/index.html` 时，API 提供前端静态文件与 SPA 回退；带哈希资源可长期缓存，首页不缓存，未知 API 路径返回 404。
