# Luvia Server 候选

## 环境变量

- `TRUST_PROXY`：默认不信任反向代理。部署在反向代理后时设置为可信代理的跳数（只有一层代理时为 `1`），否则所有客户端共用代理地址，登录限速会对全站生效。不支持 `true`：它会采用客户端可伪造的最左侧转发地址，使限速失效。应确保客户端不能绕过可信代理直接访问服务。
- `COOKIE_SECURE`：默认在 `NODE_ENV=production` 时为 `true`，会话与分享 Cookie 带 `Secure`。通过纯 HTTP 内网访问时可显式设置 `COOKIE_SECURE=false`；启用 HTTPS 时应保持默认或设置为 `true`。

当前包提供 API 与 worker 双进程入口，契约中的接口已全部实现。容器镜像尚未完成 Linux 环境验收，不能用于生产数据或接管 v1。

已实现账户偏好深度合并、壁纸令牌配置与随机浏览的直接目录和排除筛选。会话写请求使用 `X-Luvia-Request: 1`，Bearer 令牌请求不依赖该标头。

管理员可创建、查询和控制作业；`/api/v2/events` 提供作业与媒体库变化事件，受目录限制的用户只接收包含可访问目录的媒体库事件。单个 API 进程内每用户最多保持 8 条 SSE 连接。worker 接入扫描、旧库导入、元数据、批量缩略图、媒体缓存、视频预览、HLS 转码、缓存淘汰和健康检查。

扫描会物化真实目录层级与计数，并按媒体库排除规则跳过系统目录。文件夹接口按用户权限过滤，包括旧版接口中祖先目录的统计，并根据设置决定是否展示宿主机路径；Linux 挂载解析支持 `LUVIA_HOST_PATHS` 映射。

扫描成功后记录媒体库的最近扫描时间；读取异常时保留已有索引并标记不可用，重试已完成但含错误的扫描时重新检查目录。
完整扫描会将未见文件和目录标记为缺失，在配置的宽限期内保留媒体 ID 与关联；后续扫描确认恢复时清除缺失状态，到期后清理关联。缺失宽限期为零时，标记后的下一次完整扫描清理。过期缩略图等缓存文件使用持久清理队列，worker 启动或扫描后继续处理。
缺失媒体与目录从浏览、统计、搜索、下载、分享和旧版接口隐藏；管理员概览单独统计宽限期内的缺失媒体。月份统计在重建期间使用实时查询，worker 分批恢复物化统计。

管理员可管理媒体库、目录选择与站点设置。新挂载默认不会自动启用；启用自动发现后，worker 启动时会为候选挂载创建媒体库并排队扫描。默认每天按服务器本地时间 04:00 扫描，也可选择间隔或手动扫描；共享调度状态保证多 worker 不重复排队，仅启用的媒体库参与。媒体数量估计由 worker 在前两层异步抽样。
旧版配置没有媒体库路径时，仅显式设置的 `MEDIA_ROOT` 可作为导入回退；未设置时不会把候选挂载自动创建为媒体库。
旧收藏首次扫描未命中时保留为 `unmatched`；后续扫描会重新匹配可解析的路径并更新导入作业计数。
媒体库存在嵌套时，旧收藏按根路径由深到浅匹配，选择已启用、实际收录目标且用户有权访问的第一个库；无可访问候选时保留待匹配记录。

管理员可管理用户和虚拟目录权限；重置密码会撤销该用户的会话，系统会保留至少一名管理员。用户自行修改密码或管理员重置密码只撤销登录会话，不撤销该账户的 API 令牌与壁纸令牌（2026-11-06 决定，避免改密码导致壁纸客户端等集成失效）；需要停用令牌时单独撤销。

管理员概览展示媒体、缓存、作业和 API 运行指标。分钟曲线中尚无采样的时间点为 0；日志使用脱敏的结构化输出，客户端错误保留 HTTP 状态且不写入错误日志，worker 日志经有界的数据库中转进入 API 内存环形缓冲。

相册支持手动选择媒体或保存智能筛选条件，列表与封面按当前用户可访问的目录计算；智能相册的媒体查询同时应用保存的筛选条件和请求筛选条件。筛选候选、筛选后的时间分桶和相册汇总通过只读查询线程执行，线程数和等待队列有上限。

分享支持媒体、文件夹和相册目标，可设置密码、过期时间及原文件下载权限。访客资源访问检查分享状态、目标成员和所有者当前目录权限；禁用的媒体库不出现在媒体结果中。同一分享的视频按媒体共享 HLS 转码产物，每次读取均检查分享权限。

下载接口签发十分钟有效的一次性票据，使用 ZIP 存储模式流式打包；打包时逐项核验会话、目录权限和媒体真实路径。单个 API 进程内每用户最多同时下载 2 个 ZIP，超限时票据仍可重试。

扫描成功后会排队提取元数据：图片读取 EXIF、方向和 GPS，音视频通过 ffprobe 读取编码与时长；拍摄时间依次使用元数据、文件名和修改时间。元数据按批次续跑，文件租约防止多个 worker 重复处理。原文件及浏览器可解码图片提供 Range 和 ETag。图片及视频缩略图、ThumbHash、静音视频预览、需转换的显示版本及深度缩放瓦片由 worker 生成，缓存按访问时间淘汰。

缩略图就绪状态随源文件变化和缓存淘汰更新；生成与淘汰时同步调整受影响文件夹封面。工作进程通过可取消的只读子进程统计缓存总量，再按访问时间排队清理；统计期间发生的并发写入由后续周期继续检查。
元数据改变拍摄时间后，worker 增量刷新相关目录及祖先的时间与封面并发送媒体库事件；扫描租约有效时延后刷新，进程重启后恢复待处理目录。

HEIC/HEIF 使用 FFmpeg 解码后生成显示图和缩略图；相机 RAW 格式尚未接入解码和扫描。

媒体详情返回提取到的 EXIF、位置、视频信息、目录面包屑和当前用户的手动相册，并检查目录访问权限。WebP 的 EXIF 通过图片解码器提取后解析。

管理员可在 `/editor` 上传 JPEG、PNG、WebP 或 GIF 图片（最大 128 MiB），生成后选择媒体库及相对文件夹导入新副本；后端会按用户隔离暂存、过期回收，禁止覆盖同名文件并对已确认导入执行恢复。Linux 通过目录句柄固定目标位置；异常状态保留记录供核验。

图像修复接口通过 `EDITOR_SERVICE_URL` 对接独立推理服务；服务未配置或不可达时模型不可用。输入按 EXIF 方向校正，蒙版映射到原图尺寸，结果须保持原图宽高；保存副本会保留结果的 ICC 色彩配置并写入拍摄时间，其他原始 EXIF 字段尚未完整继承；高位深图片暂不支持修复。单图默认上限由 `EDITOR_MAX_IMAGE_PIXELS` 控制，默认 1 亿像素。超过模型单次输入上限时按蒙版区域分块并保留上下文，只合成选区，非 RGB 原图统一转换为 sRGB；大范围修复的接缝与细节需实际验收。蒙版最长边默认 2048 像素，放大到原图时存在画笔精度限制。`EDITOR_MAX_RESULT_BYTES` 限制单个推理结果，默认 512 MiB。磁盘删除要求媒体库可写，并核对源版本和文件身份；目录暂存与持久化阶段用于恢复中断。若删除结果无法确认，接口返回 `OPERATION_PARTIAL` 并保留索引，应核验媒体库挂载与同目录 `.luvia-delete-<操作编号 SHA-256>` 暂存目录；不要手动删除暂存文件。完整契约见 [媒体失败治理与图像修复设计](../../docs/MEDIA_FAILURE_AND_EDITOR_DESIGN.md)。

回忆接口提供往年同日、最近加入与随机媒体；搜索联想覆盖可访问的文件夹、相册、相机型号和媒体。

旧版登录、列表、原文件、缩略图和目录入口支持基础兼容；列表支持旧版排序、筛选和种子分页，目录支持收藏、搜索和封面。壁纸令牌在随机、旧版列表及媒体读取时按保存的来源、方向与媒体类型限制访问。旧版用户自定义附加字段未迁移，搜索细节和真实旧客户端行为仍需验证。
旧版 JWT 使用显式注入的 `JWT_SECRET`，缺省时使用旧数据目录中的密钥文件；新签发的旧版登录 JWT 绑定账户，密码重置或账户删除后失效。导入的旧壁纸令牌只能通过已登记的令牌记录鉴权。
导入记录保留旧账户与令牌的来源，重复运行导入不会恢复已删除账户或已撤销令牌；旧用户名与现有账户冲突时不会自动绑定。升级已运行过旧版导入的数据库时，无法可靠识别先前撤销的令牌，故不会自动补发旧账户或令牌。迁入的旧壁纸 JWT 在使用时校验签名、用户和原始有效期；旧密钥不可用时需重新创建令牌。
首次导入未找到可用的旧管理员，或升级后无法确认旧账户是否已经导入时，作业会报错并保留初始化阻断，需要管理员结合备份和旧配置核验，不能直接对外开放初始化。
导入的旧壁纸令牌默认浏览媒体库、保留竖图和尺寸未知图片，并沿用旧视频开关与有效的播放间隔。
旧配置中当前登记的壁纸令牌可迁入；仍在旧客户端中使用但未保存在旧配置里的历史令牌需要重新创建。旧壁纸配置中的 `mode`、`path`、`showInfo` 尚未保留，旧版登录响应也未保留用户自定义扩展字段。

扫描和媒体转换当前覆盖常见浏览器图片、HEIC/HEIF 与 TIFF；相机 RAW 文件尚未索引或解码，需要补充解码管线并用真实格式夹具验证。
旧版分片 WebP 缓存位于同一 `CACHE_DIR` 且未早于源文件时，新中图生成期间可作为临时显示；后台生成完成后使用 v2 缓存。

使用 Node 24 运行当前测试和类型检查：

```sh
npx -y -p node@24 -- pnpm --filter @luvia/server test
npx -y -p node@24 -- pnpm --filter @luvia/server typecheck
npx -y -p node@24 -- pnpm --filter @luvia/server bench
```

基准默认生成一百万条合成媒体，并在独立进程持续扫描合成文件时测量默认读取路径；临时数据库在结束时删除。无筛选时间线使用物化月份统计，筛选查询与真实 NAS I/O 仍需另行测量。

生成本机联调素材（需要 FFmpeg，目标同名文件存在时拒绝覆盖）：

```sh
npx -y -p node@24 -- pnpm --filter @luvia/server fixtures --output /path/to/fixture
```

使用 Node 24 启动本地双进程：

```sh
DATA_DIR=./data CACHE_DIR=./cache MEDIA_ROOT=/path/to/fixture npx -y -p node@24 -- pnpm --filter @luvia/server dev
```

`/healthz` 检查 API 能否响应，`/readyz` 还要求 worker 心跳有效且未过期。worker 启动时探测 FFmpeg 和 NVENC 单帧编码能力；探测结果可从管理员系统接口读取。在 macOS 开发环境中，`MEDIA_ROOT` 指定本地合成媒体目录；Linux 环境以 mountinfo 中检测到的候选挂载限制扫描范围。
worker 心跳中的 `memory` 保存该 Node 进程的 RSS、V8 堆和外部分配字节数；`arrayBuffers` 包含在 `external` 中，FFmpeg 子进程不包含在内。多个 worker 共用一条心跳记录，其数值来自最后写入的进程。
worker 每 15 分钟在独立线程执行 SQLite 检查点截断与 `PRAGMA optimize`；有活跃读取者时不等待锁，并在下次维护时重试。

数据库升级后，worker 自动运行一次存量媒体索引回填，按批记录设备号、inode、毫秒修改时间与前 64 KiB 的 SHA-256。回填断点和读取失败数保存在 `index_backfill` 表，重启后可续跑；单个文件不可读不会阻断其它文件。

每个启用且未关闭监控的媒体库由一个 worker 持有租约并运行协调器，配置变更后重新建立；失租后写入受租约代次保护。`auto` 在网络文件系统或估算监视额度不足时轮询，`watch` 强制实时监视且额度不足时降级，`poll` 按设置间隔全量对账，`off` 关闭实时监控。受限用户收到的变化事件只含其有权访问的目录；事件同时涉及无权目录时，四项计数置零，只作为刷新通知。监控和全量扫描共用挂载校验：身份由文件系统类型、来源和文件系统内路径组成；首次建立或身份变化时，对已有未缺失文件随机抽取最多 200 个，至少 90% 的样本需匹配大小和修改时间（有毫秒时间时按毫秒比对，升级前尚未回填的记录按秒比对），才能接受身份。校验失败时停止实时写入与扫描缺失标记，恢复后排队全量对账。实时索引端口独占 SQLite 连接；停止时先释放租约，再等待协调器结束并关闭端口与连接。扫描占用期间被拒绝的实时写入保留为脏目录并在锁释放后重试。监控全量对账请求保留至扫描成功，失败后按 1、5、15、60 分钟退避，错误原因写入作业和 worker 日志。

监控根目录检查在独立进程中执行并设置超时，各媒体库并发检查，租约由独立心跳续期。工作进程收到停止信号后立即停止监控，最长等待 12 秒；超时后退出，未释放的租约依靠到期机制接管。

媒体库事件保留实际涉及的目录，供 SSE 按用户目录权限过滤；统计数字表示媒体变化。扫描事件按作业持久记录受影响目录；扫描失败、停止或被其他扫描接替时，已经提交的变化仍会发布，目录移动中尚未读取的媒体由后续扫描接续确认。元数据刷新使用同一持久节流队列。

Linux 系统信息的监视数按本服务存活 worker 的进程 inotify 计数汇总；内核上限按用户 ID 共享，其他进程或容器占用未包含在该统计中。多个媒体库共用进程监视器时，无法可靠拆分每库的内核监视数，单库 `watchedDirs` 显示为未知。新增文件稳定后立即落库，随后识别为移动时保留原媒体 ID 并抵消临时新增计数。

多个 worker 通过共享数据库中的租约限制 FFmpeg 和缩略图并发，逐文件预览作业的领取数也受视频并发设置约束；长视频转码期间仍可处理其他作业。相同缩略图请求共享作业；最多 32 个请求同时等待，超出时返回待处理。最后一个等待客户端断开时取消按需作业和 FFmpeg，批量任务依赖的作业继续执行。已进入 sharp 的操作在完成后检查取消状态；逐媒体缓存生成时，媒体锁或处理槽位被接管后，旧持有者不能提交缓存。每个媒体的排队、运行和暂停瓦片作业最多 8 个。登录用户的 HLS 按访问会话隔离，分享访客在同一分享内按媒体复用；排队、运行及暂停的 HLS 作业，登录用户合计最多 8 个，分享访客合计最多 2 个且同一分享最多 1 个。分片生成后即可播放；30 秒无访问时停止转码，闲置 60 秒后回收会话缓存。活跃播放的分片暂不参与缓存淘汰。支持探测 NVENC 并在不可用时回退 CPU；其他硬件编码路径尚未验证。

工作进程启动作业池后开始发送心跳，缺失或过期的心跳会使就绪检查失败；事件循环 p99 继续显示在服务指标中。心跳反映进程和写入活动，持续作业领取失败需要结合日志判断。视频元数据的完整探测失败时，后台可使用共享 FFmpeg 槽位提取最多 2 MiB 的单帧样本；仅在原容器创建时间可用时记录拍摄时间，音轨、原容器和时长保持未知，已有尺寸保留。预览转码失败且探测不到视频包时报告文件无可读取视频包。定向缩略图恢复不覆盖已有缓存，损坏 JPEG 的宽松解码可能产生不完整画面。

新的视频缩略图从有限的片段中选择非黑画面，未找到时使用首帧；已有缓存按原版本保留。预览视频遇到普通封装失败时可规范帧率重试，子进程被系统终止或数据库暂时繁忙时不会进入编码回退。浏览请求通过有限期标记优先调度，HLS 与预览共同受 FFmpeg 领取上限约束。

现有测试使用临时合成数据，不代表真实旧库迁移或生产环境验收。作业领取与扫描锁使用独立租约代次，扫描支持目录级断点。旧版导入只迁移用户数据并保留待匹配收藏；完整生产迁移、媒体管线与端到端性能尚未验收。

根目录的 Dockerfile 和 Compose 配置使用同一 Node 24 镜像运行 API 与 worker，媒体挂载为只读；应用目录由 root 持有且运行用户不可写，数据与缓存目录由运行用户持有。可按 Compose 注释启用 NVIDIA 设备。容器构建、卷权限、GPU 与前端资源尚需在 FNOS 验证，当前后端仍不可用于生产。

存在 `apps/web/dist/index.html` 时，API 提供前端静态文件与 SPA 回退；带哈希资源可长期缓存，首页不缓存，未知 API 路径返回 404。

壁纸作用域令牌访问旧版 `/api/library/folders` 时，仅列出配置目录及其子树；未选择目录时返回空列表，来源为全部或收藏时返回 403。旧版随机壁纸获取接口继续按壁纸配置工作。
