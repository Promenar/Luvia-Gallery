# 媒体失败治理与查看器编辑设计

## 目标与范围

面向近百万媒体的图库，限制同一媒体处理连续失败，提供可管理的忽略清单、原图查看和经用户确认的磁盘删除，并为查看器提供旋转及 LaMa、MI-GAN、SLBR 图像修复。前端沿用现有页面、组件和主题；由前端负责人实现。本文为对接设计，接口标注实现状态；未标注“已实现”的均为拟定契约。

### 现有事实

- 浏览请求可调用 `enqueueMediaTask`；其去重约束只覆盖排队、运行和暂停的作业，失败后新的请求可以创建新作业。单次批量缩略图遍历在文件失败后继续处理其他文件。此前观察到重复创建，不能据此断定任务无限重试。
- 图像缩略图由 Sharp/libvips 生成；视频使用 FFmpeg。原文件访问采用媒体 ID、授权检查及 `secureMediaPath`，不接受客户端提交的物理路径。
- 生产媒体目录 `/media` 和 `/video` 当前为只读挂载，直接删除原文件和在媒体库保存新文件均需要管理员配置可写挂载及操作系统权限。此前采样 API 与 worker 容器均健康；截图中的 58 个缩略图和 40 条拍摄信息缺失仍待逐项诊断。
- 保留现有缩略图及缓存，不触发全库重建。源文件、缓存键、原图或既有媒体身份不得因启用本功能而批量变化。

| 能力 | 前端 | 后端 |
| --- | --- | --- |
| 失败治理 | 忽略列表、筛选、原因、次数、查看原图、单项解除/重试及删除确认 | 记录按媒体和处理类型划分的失败、限制自动重试、查询及管理接口 |
| 查看器 | 在现有工具栏添加旋转、删除、修复；图片上显示放大光标，瀑布流普通光标 | 提供能力和受授权的原图/删除/保存接口 |

## 失败与忽略模型

以媒体 ID、源文件版本（`size`、`modified_at`、`cache_generation`）和具体处理操作为键，操作至少区分缩略图尺寸、预览、元数据。每项操作分别记录连续失败次数、最近失败时间、可安全展示的摘要和是否忽略；缩略图不同尺寸独立计数，避免一个尺寸成功掩盖另一尺寸持续失败。成功仅清除对应操作的连续失败。源版本改变后旧记录不阻塞新版本，仍应在管理界面可追溯或清理。缺失、权限或存储暂时不可用应分类显示，不能全部归因于编码。

默认同一源版本同一类别**连续失败 3 次**后自动忽略该类别，计数是 3 次实际失败（含首次），不是额外重试 3 次。如引入主动自动重试，须采用延时退避；达到上限后所有自动入口都应检查，包括前台按需缓存、全库任务、元数据批次和恢复任务。请求可立即得知已忽略，不能无限返回 202。因取消、租约丢失、服务停机、SQLite 暂时繁忙导致的放弃不计为媒体处理失败。记录失败和作业状态变更须在同一数据库事务、持有有效租约时完成。自动忽略不删除文件、不阻止其他处理类别和查看原图。

管理员的“重试”重置该类别计数并安排一次定向处理；“解除忽略”仅恢复自动调度，不删除历史文件。恢复前重新检查源版本和媒体权限。列表支持分页、类别、状态、关键词及稳定排序；返回源版本、失败原因和次数，查看器通过现有媒体 ID 打开。缺失、无法解码或访问受限时显示可理解的原因，不能承诺所有原文件均可显示。

## 磁盘删除

仅管理员会话可删除；界面显示文件名和明确的不可撤销提示，用户确认后提交媒体 ID 与已查看的源版本。后端重新验证会话、CSRF、媒体库启用与权限、实际路径位于配置的媒体库内、目标仍为同一普通文件、源版本未变化并具有写权限；不接受客户端绝对路径。只读时返回 `MEDIA_READ_ONLY`，源变化时返回 `MEDIA_CHANGED`。不得在确认前删除，不能误删符号链接目标或目录。

删除前核对索引中的精确修改时间、设备及 inode；存在文件头指纹时同时核对指纹，缺少必要身份信息时先扫描。操作以 SQLite 写事务协调多个 API 进程，先将目标移入同目录的私有暂存目录并再次核对身份，记录阶段后删除并更新索引。进程中断后可以用同一操作编号恢复能够确认的阶段；若文件或挂载状态不足以证明结果，返回 `OPERATION_PARTIAL` 并保留索引，需核验原路径、挂载与暂存目录。目录移动、挂载变化和外部程序持有写句柄时应暂停整理操作，当前未提供跨程序锁；数据库为 WAL/NORMAL，尚未验证整机断电的持久性。删除只影响用户选择的单项；缓存按既有规则回收，不触发全库重建。

## 查看器旋转

查看器提供顺时针 90° 操作，预览旋转不覆盖原文件；切换媒体时复位，缩放、平移和图片适配按旋转后的边界计算。若需要将旋转持久保存，复用“保存副本”，以显式动作生成新文件；保留源文件及原 EXIF 方向语义，避免重复旋转。支持持久旋转的格式、元数据保留与画质必须经实际实现和测试确认。

## 图像修复

### 能力与交互

- `migan`：按用户蒙版修复。官方 ONNX 管线接收 RGB 图与单通道二值蒙版，掩膜约定由服务端适配上游。
- `lama`：按用户蒙版修复。推理引擎、预处理及权重须分别核验，不能将 macOS Core ML 实现当作 Linux/CUDA 实现。
- `slbr`：提供水印检测及修复候选；自动识别质量与输出需用实际模型验证。识别结果允许用户调整，服务端不能宣称一定可识别或无损还原。

前端把蒙版映射到原图的像素坐标，考虑 EXIF 方向、旋转与缩放；修复预览只读原图。预览结果可对比、取消及重新生成；“保存副本”单独确认文件名，不覆盖原图。保存到原媒体库需要可写权限，返回新媒体 ID 并按现有扫描机制入库；保存失败不影响原图和已有缓存。

### 后端运行

推理与 Node API/worker 主线程隔离，适配 CPU 与可用 GPU；模型按需加载与复用，限制同时运行的推理任务和输入像素，允许取消并回收临时文件。按模型实际能力支持 GPU/CPU，GPU 不可用或资源不足时返回可操作状态或回退，不能把固定硬件并发写死。模型代码、权重来源、许可、哈希及版本分别登记；首次使用与下载行为应明确，不把权重或私有媒体上传到第三方。检查运行环境、峰值显存、内存、延迟、质量、异常退出及清理，报告测试图像尺寸和是否与其他 GPU 任务并发。

FNOS 实测为 32 逻辑线程、GTX 1660 Ti 6 GB；采样时约 4.3 GB 已被占用。该信息不能证明三模型能同时运行，也不能推断耗时。各模型分别在隔离环境用代表性输入测量，再决定默认执行设备及资源分配。

以下为前后端对齐目标；接口及字段以最终代码中的 `packages/contracts` 为准。写操作均要求管理员 Cookie 会话及现有 CSRF 头；所有 ID 为服务端生成，错误体沿用现有 API 格式。

## 实施与验收

1. 后端先建立失败治理与事务约束：复现失败后反复建任务，增加失败限额、持久化和全部自动入口检查，测试并发、租约、源变化、成功清零、重试及旧数据库兼容。
2. 后端实现忽略列表和管理 API，测试管理员权限、CSRF、分页、不可查看原文件与手动恢复。
3. 后端设计受控写入及删除，使用隔离目录测试真实磁盘操作、只读与中断恢复；线上媒体挂载的更改单独纳入发布计划。旋转先在前端预览，保存副本复用写入能力。
4. 后端逐一核验模型来源、权重许可与执行格式，完成 CPU/GPU 适配及隔离资源测试，再提供编辑 API；以真实测试结果标注可用能力，不以接口桩冒充模型可用。
5. 前端依照接口实现页面，复用现有控制台 `Section`、`Chip`、`Confirm` 和查看器 `.lv-vt`/`.lv-vb` 等结构与主题令牌；不重新设计现有界面。展示失败、只读、处理中、可取消和空状态。原图访问失败不隐藏其他操作。
6. 集成验收覆盖忽略与解除、查看原图、确认删除、旋转、模型修复对比及保存副本；验证刷新、重启、浏览器权限、有限显存、普通用户隔离，以及现有缩略图文件与计数不被批量重建。记录尚未覆盖的模型和部署环境。

## 前端交付清单

控制台继续使用现有分区和视觉体系，在“扫描与处理”中增加“处理失败”入口及失败计数；点击后展示分页列表，列出文件名、媒体库虚拟路径、操作、失败次数、最近原因和时间。列表为空、查询中、无权限、原图不可读、任务执行中及源版本变化均有明确状态。每项提供“查看原图”“重试”“解除忽略”和“删除”；不同操作的失败分别显示，删除需再次确认。已忽略与未忽略可筛选，列表刷新及操作结果按服务器响应更新。

查看器在现有顶部 `.lv-vt` 工具栏中加入旋转、修复、删除图标，使用现有 `.lv-vb` 控件、无障碍名称及键盘焦点；继续保留关闭、播放、收藏、下载、信息、前后翻页与胶片条。图片悬停时使用放大光标，放大后沿用抓手光标；瀑布流图块恢复普通光标。选择修复后在查看器内展示蒙版画笔、模型及结果预览，沿用现有组件和主题；不改变已有页面的整体布局。

客户端先调用能力接口决定是否启用编辑及保存按钮；能力接口已实现，模型可用性由外部推理服务探测决定。未部署推理服务时三个模型均不可用，前端不显示修复入口；不能把接口桩当作模型可用。失败管理接口示例响应：

```json
{
  "items": [{
    "id": "12", "mediaId": "example-media-id", "libraryId": "example-library",
    "name": "example.jpg", "folder": "example-library/示例目录", "operation": "thumb:s",
    "source": { "size": 1234, "modifiedAt": 1700000000, "generation": 0 },
    "failures": 3, "ignored": true, "category": "decode", "reason": "图片无法解码，请检查文件完整性及格式支持",
    "lastFailedAt": "2026-11-07T03:00:00.000Z"
  }],
  "nextCursor": null, "total": 1, "counts": { "unignored": 0, "ignored": 1 }
}
```

`source` 原样用于重试与解除忽略，`modifiedAt` 为 Unix 秒；失败 `id` 是不透明字符串。`operation` 当前可能为 `thumb:s`、`thumb:m`、`thumb:l`、`preview`、`metadata`、`dimensions`、`display` 或 `tile:级别:列:行`。列表只返回源版本仍匹配的记录。当前未实现类别/关键词筛选、SLBR 自动检测、主动退避重试和批量管理；删除、旋转与蒙版修复已在当前工作树实现，模型是否可用以能力接口为准。

管理接口鉴权复用现有管理员会话；写请求发送 `X-Luvia-Request: 1`。`POST .../:id/retry` 返回 `{ "jobId": "..." }`，后台已有同媒体库拍摄信息任务时返回 409；`POST .../:id/unignore` 返回 `{ "success": true }`，仅删除失败记录，不会直接提交作业。媒体已变化时返回 409 和 `MEDIA_CHANGED`；其他并发冲突返回 409 和 `CONFLICT`，未知或已删除记录返回 404。访问已忽略的缓存返回 409，错误码 `MEDIA_IGNORED`。这些接口仍须完成全量回归和生产环境验证。

列表的 `counts` 按当前有效源版本统计，与忽略状态筛选及分页无关；`total` 应用忽略状态筛选但不受分页游标影响，均按失败操作条数计数。`MediaItem`/`MediaDetail` 的 `source` 在当前工作树已返回；过渡期类型可选，以兼容尚未升级的服务，前端必须在收到实际版本后才启用需要源版本的写操作。`source` 是乐观并发令牌，不能代替文件打开、身份和写权限的服务器端校验。

### 蒙版与保存的前后端约定

蒙版坐标统一为原图经过 EXIF 方向校正、尚未应用查看器旋转时的像素空间；后端也必须先自动校正 EXIF 方向。客户端撤销查看器旋转及缩放后发送蒙版 PNG：白色 255 表示需要修复，黑色 0 表示保留。请求使用 `{data, width, height}`，其中 `data` 是不含 data URL 前缀的 PNG base64。蒙版长边不得超过能力接口的 `mask.maxEdge`，宽高比必须与原图一致；后端把蒙版转为单通道二值 PNG 并以最近邻方式缩放到校正后的原图尺寸。`mask.maxBytes` 约束 base64 解码后的 PNG 字节数；HTTP 请求体限制须容纳 base64 膨胀，同时在图像解码前检查输入长度与像素上限。精确上限由已启用模型的能力接口返回。

`models[].features` 中 `mask` 表示接受用户蒙版，`detect` 表示支持自动检测；可用性、执行设备及输入限制由后端实测能力决定。创建推理作业返回 `{id,status}`；查询返回状态、`progress` 和 `stage`，失败提供稳定错误码。保存副本成功返回 `{status:'saved',mediaId,name,folder}`；若文件已写入但索引失败，返回 `{status:'pending',mediaId:null,name,folder}`，由下一次扫描补入，不能把尚未可用的媒体 ID 当作成功。`operationId` 与管理员、目标媒体、源版本及操作内容绑定，持久记录并幂等重放；重复 ID 携带不同请求返回冲突。

### 推理服务契约

Node 侧只实现协议、队列、存储与权限，模型加载和 GPU 调度放在独立服务中，避免把 Python/ONNX 运行时塞进 API 或 worker 主线程。服务通过 `EDITOR_SERVICE_URL` 配置，`EDITOR_SERVICE_TOKEN` 可选；未配置或不可达时能力接口必须返回全部模型不可用，前端隐藏修复入口。

独立服务的实现与部署说明见 [推理服务 README](../apps/inference-service/README.md)。服务按需加载本地模型，单实例串行推理，仅在蒙版区域合成修复结果，并拒绝当前管线无法无损处理的高位深图像。
