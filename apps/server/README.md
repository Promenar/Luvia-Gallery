# Luvia Server 候选

## 环境变量

- `TRUST_PROXY`：默认不信任反向代理。部署在反向代理后时设置为可信代理的跳数（只有一层代理时为 `1`），否则所有客户端共用代理地址，登录限速会对全站生效。不支持 `true`：它会采用客户端可伪造的最左侧转发地址，使限速失效。应确保客户端不能绕过可信代理直接访问服务。
- `COOKIE_SECURE`：默认在 `NODE_ENV=production` 时为 `true`，会话与分享 Cookie 带 `Secure`。通过纯 HTTP 内网访问时可显式设置 `COOKIE_SECURE=false`；启用 HTTPS 时应保持默认或设置为 `true`。

当前包提供 API 与 worker 双进程入口，并包含数据库、安全、查询、扫描和迁移模块的部分实现。完整接口和媒体管线尚未就绪，不能用于生产数据或接管 v1。

已实现账户偏好深度合并、壁纸令牌配置与随机浏览的直接目录和排除筛选。会话写请求使用 `X-Luvia-Request: 1`，Bearer 令牌请求不依赖该标头。

管理员可创建、查询和控制作业；`/api/v2/events` 提供作业与媒体库变化事件，受目录限制的用户只接收包含可访问目录的媒体库事件。单个 API 进程内每用户最多保持 8 条 SSE 连接。worker 接入扫描、旧库导入、元数据、批量缩略图、媒体缓存、视频预览、HLS 转码、缓存淘汰和健康检查。

扫描会物化真实目录层级与计数，并按媒体库排除规则跳过系统目录。文件夹接口按用户权限过滤，包括旧版接口中祖先目录的统计，并根据设置决定是否展示宿主机路径；Linux 挂载解析支持 `LUVIA_HOST_PATHS` 映射。

扫描成功后记录媒体库的最近扫描时间；读取异常时保留已有索引并标记不可用，重试已完成但含错误的扫描时重新检查目录。
完整扫描会将未见文件和目录标记为缺失，在配置的宽限期内保留媒体 ID 与关联；后续扫描确认恢复时清除缺失状态，到期后清理关联。缺失宽限期为零时，标记后的下一次完整扫描清理。过期缩略图等缓存文件使用持久清理队列，worker 启动或扫描后继续处理。

管理员可管理媒体库、目录选择与站点设置。新挂载默认不会自动启用；启用自动发现后，worker 启动时会为候选挂载创建媒体库并排队扫描。间隔扫描由共享调度状态去重，仅为启用的媒体库排队。媒体数量估计由 worker 在前两层异步抽样。
旧版配置没有媒体库路径时，仅显式设置的 `MEDIA_ROOT` 可作为导入回退；未设置时不会把候选挂载自动创建为媒体库。
旧收藏首次扫描未命中时保留为 `unmatched`；后续扫描会重新匹配可解析的路径并更新导入作业计数。
媒体库存在嵌套时，旧收藏按根路径由深到浅匹配，选择已启用、实际收录目标且用户有权访问的第一个库；无可访问候选时保留待匹配记录。

管理员可管理用户和虚拟目录权限；重置密码会撤销该用户的会话，系统会保留至少一名管理员。

管理员概览展示媒体、缓存、作业和 API 运行指标。分钟曲线中尚无采样的时间点为 0；日志使用脱敏的结构化输出，客户端错误保留 HTTP 状态且不写入错误日志，worker 日志经有界的数据库中转进入 API 内存环形缓冲。

相册支持手动选择媒体或保存智能筛选条件，列表与封面按当前用户可访问的目录计算；智能相册的媒体查询同时应用保存的筛选条件和请求筛选条件。筛选候选、筛选后的时间分桶和相册汇总通过只读查询线程执行，线程数和等待队列有上限。

分享支持媒体、文件夹和相册目标，可设置密码、过期时间及原文件下载权限。访客资源访问检查分享状态、目标成员和所有者当前目录权限；禁用的媒体库不出现在媒体结果中。分享视频按媒体共享 HLS 转码产物，每次读取均检查分享权限。

下载接口签发十分钟有效的一次性票据，使用 ZIP 存储模式流式打包；打包时逐项核验会话、目录权限和媒体真实路径。单个 API 进程内每用户最多同时下载 2 个 ZIP，超限时票据仍可重试。

扫描成功后会排队提取元数据：图片读取 EXIF、方向和 GPS，音视频通过 ffprobe 读取编码与时长；拍摄时间依次使用元数据、文件名和修改时间。元数据按批次续跑，文件租约防止多个 worker 重复处理。原文件及浏览器可解码图片提供 Range 和 ETag。图片及视频缩略图、ThumbHash、静音视频预览、需转换的显示版本及深度缩放瓦片由 worker 生成，缓存按访问时间淘汰。

缩略图就绪状态随源文件变化和缓存淘汰更新；生成与淘汰时同步调整受影响文件夹封面。
元数据改变拍摄时间后，worker 增量刷新相关目录及祖先的时间与封面并发送媒体库事件；扫描租约有效时延后刷新，进程重启后恢复待处理目录。

HEIC/HEIF 使用 FFmpeg 解码后生成显示图和缩略图；相机 RAW 格式尚未接入解码和扫描。

媒体详情返回提取到的 EXIF、位置、视频信息、目录面包屑和当前用户的手动相册，并检查目录访问权限。

回忆接口提供往年同日、最近加入与随机媒体；搜索联想覆盖可访问的文件夹、相册、相机型号和媒体。

旧版登录、列表、原文件、缩略图和目录入口支持基础兼容；列表支持旧版排序、筛选和种子分页，目录支持收藏、搜索和封面。壁纸令牌在随机、旧版列表及媒体读取时按保存的来源、方向与媒体类型限制访问。旧版用户自定义附加字段未迁移，搜索细节和真实旧客户端行为仍需验证。
旧版 JWT 使用显式注入的 `JWT_SECRET`，缺省时使用旧数据目录中的密钥文件；新签发的旧版登录 JWT 绑定账户，密码重置或账户删除后失效。导入的旧壁纸令牌只能通过已登记的令牌记录鉴权。
导入记录保留旧账户与令牌的来源，重复运行导入不会恢复已删除账户或已撤销令牌；旧用户名与现有账户冲突时不会自动绑定。升级已运行过旧版导入的数据库时，无法可靠识别先前撤销的令牌，故不会自动补发旧账户或令牌。迁入的旧壁纸 JWT 在使用时校验签名、用户和原始有效期；旧密钥不可用时需重新创建令牌。
首次导入未找到可用的旧管理员，或升级后无法确认旧账户是否已经导入时，作业会报错并保留初始化阻断，需要管理员结合备份和旧配置核验，不能直接对外开放初始化。
导入的旧壁纸令牌默认浏览媒体库、保留竖图和尺寸未知图片，并沿用旧视频开关与有效的播放间隔。
旧配置中当前登记的壁纸令牌可迁入；仍在旧客户端中使用但未保存在旧配置里的历史令牌需要重新创建。旧壁纸配置中的 `mode`、`path`、`showInfo` 尚未保留，旧版登录响应也未保留用户自定义扩展字段。

扫描和媒体转换当前覆盖常见浏览器图片、HEIC/HEIF 与 TIFF；相机 RAW 文件尚未索引或解码，需要补充解码管线并用真实格式夹具验证。
旧版分片 WebP 缓存位于同一 `CACHE_DIR` 且未早于源文件时，新中图生成期间可作为临时显示；后台生成完成后使用 v2 缓存。

使用 Node 24 运行当前测试和类型检查：

```sh
npx -y -p node@24 -- pnpm --filter @luvia/server test
npx -y -p node@24 -- pnpm --filter @luvia/server typecheck
npx -y -p node@24 -- pnpm --filter @luvia/server bench
```

基准默认生成一百万条合成媒体，并在独立进程持续扫描合成文件时测量默认读取路径；临时数据库在结束时删除。无筛选时间线使用物化月份统计，筛选查询与真实 NAS I/O 仍需另行测量。

生成本机联调素材（需要 FFmpeg，目标同名文件存在时拒绝覆盖）：

```sh
npx -y -p node@24 -- pnpm --filter @luvia/server fixtures --output /path/to/fixture
```

使用 Node 24 启动本地双进程：

```sh
DATA_DIR=./data CACHE_DIR=./cache MEDIA_ROOT=/path/to/fixture npx -y -p node@24 -- pnpm --filter @luvia/server dev
```

`/healthz` 检查 API 事件循环，`/readyz` 还要求 worker 心跳正常。worker 启动时探测 FFmpeg 和 NVENC 单帧编码能力；探测结果可从管理员系统接口读取。在 macOS 开发环境中，`MEDIA_ROOT` 指定本地合成媒体目录；Linux 环境以 mountinfo 中检测到的候选挂载限制扫描范围。
worker 每 15 分钟在独立线程执行 SQLite 检查点截断与 `PRAGMA optimize`；有活跃读取者时不等待锁，并在下次维护时重试。

数据库升级后，worker 自动运行一次存量媒体索引回填，按批记录设备号、inode、毫秒修改时间与前 64 KiB 的 SHA-256。回填断点和读取失败数保存在 `index_backfill` 表，重启后可续跑；单个文件不可读不会阻断其它文件。

多个 worker 通过共享数据库中的租约限制 FFmpeg 和缩略图并发，长视频转码期间仍可处理其他作业。相同缩略图请求共享作业；最多 32 个请求同时等待，超出时返回待处理。最后一个等待客户端断开时取消按需作业和 FFmpeg，批量任务依赖的作业继续执行。已进入 sharp 的操作在完成后检查取消状态，同一缓存键的新生成会等待旧操作退出；每个媒体的排队、运行和暂停瓦片作业最多 8 个。登录用户的 HLS 按访问会话隔离，分享访客按媒体复用；排队、运行及暂停的 HLS 作业合计最多 8 个。分片生成后即可播放；30 秒无访问时停止转码，闲置 60 秒后回收会话缓存。活跃播放的分片暂不参与缓存淘汰。支持探测 NVENC 并在不可用时回退 CPU；其他硬件编码路径尚未验证。

现有测试使用临时合成数据，不代表真实旧库迁移或生产环境验收。作业领取与扫描锁使用独立租约代次，扫描支持目录级断点。旧版导入只迁移用户数据并保留待匹配收藏；完整生产迁移、媒体管线与端到端性能尚未验收。

根目录的 Dockerfile 和 Compose 配置使用同一 Node 24 镜像运行 API 与 worker，媒体挂载为只读；应用目录由 root 持有且运行用户不可写，数据与缓存目录由运行用户持有。可按 Compose 注释启用 NVIDIA 设备。容器构建、卷权限、GPU 与前端资源尚需在 FNOS 验证，当前后端仍不可用于生产。

存在 `apps/web/dist/index.html` 时，API 提供前端静态文件与 SPA 回退；带哈希资源可长期缓存，首页不缓存，未知 API 路径返回 404。
