# 大图修复与外部图片编辑

## 目标

在现有查看器和独立编辑页面中处理大于 4000 万像素的图片；模型推理在 FNOS 本地执行，预览不改写原图。用户可将修复结果保存为同目录副本、确认覆盖支持的原图，或选择媒体库和相对文件夹导入新文件。用户负责视觉质量验收。

## 职责与约束

- 页面复用现有画板、模型能力和查看器组件；后端负责大图分块、蒙版坐标映射、模型缓存、外部图片暂存、导入与权限。
- 输入和蒙版坐标均以 EXIF 方向校正后的原图为准；块带上下文，只有核心区域被合成，原始尺寸和透明通道保持不变。模型输出与缩放、跨块接缝的视觉质量由用户验收。
- 图片大小、像素与内存预算可配置；单个模型作业串行执行。模型按使用缓存并依据资源限制淘汰，显存不足时给出错误或安全释放，不能因为本机硬件而限制其他部署。
- 结果为临时预览。副本或导入使用排他创建；查看器提供需再次确认的单图原位覆盖。仅管理员会话可写入媒体库，路径必须属于所选媒体库，拒绝目录穿越和符号链接逃逸。
- 输入文件和中间结果均保存在服务端缓存目录，按用户隔离和过期回收；无第三方上传。

## 前后端接口

JSON 作业与导入接口以 `packages/contracts` 为准；原始字节上传使用 XHR 以展示进度。每个写请求带现有 CSRF 请求头。

1. `POST /api/v2/editor/uploads?name=<URL编码文件名>`：请求体为 `application/octet-stream` 图片字节。返回 `{id,name,width,height,mime,sourceUrl,expiresAt}`；`sourceUrl` 仅当前用户可访问。文件选择器、拖放和剪贴板均转换为同一上传流程。
2. `POST /api/v2/editor/jobs` 接受现有 `{mediaId,source,model,mask}`，或外部图片 `{uploadId,model,mask}`。作业查询、取消、结果预览和能力接口沿用现有接口；上传 ID 不可替换内容。
   预览后的「继续修复」以 `mask: {mode: 'continue', baseJobId, changes}` 提交新的手绘蒙版。底图是同一用户、同一原图版本的上一轮结果，保存与导入仍使用最后一轮作业。取消或失败可返回上一轮预览。
3. `POST /api/v2/editor/jobs/:id/import`：提交 `{libraryId,folder,name,operationId}`，`folder` 是所选媒体库下的相对路径，空字符串表示库根；返回 `{status,mediaId,name,folder}`。允许创建所选库内不存在的文件夹，禁止覆盖；返回的 `folder` 同样是库内相对路径。结果已写盘但索引未完成时返回 `pending`，后台尝试恢复。
4. 文件超限、类型不支持、空间不足、权限不足、过期、目标只读与无效目录均返回可展示的稳定错误码；上传和作业支持取消，关闭页面不会自动导入。
5. `POST /api/v2/editor/jobs/:id/replace-original`：提交 `{confirm:true,source,operationId}`，返回媒体 ID、新源版本和缩略图版本。Linux 服务端支持已入库单帧 JPEG、PNG、WebP；其他平台的能力接口说明不可用原因。校验源文件身份和内容，保留媒体 ID，更新索引并排队生成新缩略图。CMYK 原图覆盖时转换为 sRGB，成品颜色与修复预览一致。

页面沿用现有组件和视觉样式，支持文件选择、拖放、粘贴、蒙版绘制、模型选择、预览对比及选择目标目录；前端不读取宿主机绝对路径。支持 JPEG、PNG、WebP、GIF，上传大小上限为 128 MiB，单次图片像素上限与编辑器一致。

## SLBR 自动定位

SLBR 检测输出映射到方向校正后的原图，支持单图预览及调整蒙版，以及逐张审核或自动保存副本的批次。检测与修复共享模型缓存和串行 GPU 队列；任务持久化、限次重试并支持暂停和取消。分块检测可能漏掉小水印或误选画面，实际效果由用户检查。配置、恢复和操作方式见 [SLBR 自动修复](SLBR_AUTOMATION.md)。

## 验收

- 构造超过 4000 万像素图片、方向旋转、透明通道、跨块与稀疏蒙版，验证输出尺寸、非蒙版像素、作业取消与内存上限。
- 在 FNOS 记录三模型冷启动、热调用、切换的耗时和显存；模拟无 GPU，验证串行和可恢复的容量错误。
- 上传、作业、导入按用户和媒体库授权；验证路径逃逸、符号链接、重名、只读、缓存过期及索引失败。真实原图不作删除测试。
- 核验生产 API、worker 和本地推理服务健康，保留现有缩略图与可回滚镜像；真实页面需完成端到端验证。

## 页面行为

- 新增 `/editor` 页面（仅管理员，导航“修复”）：文件选择器、拖放、剪贴板粘贴统一走上传流程；显示上传进度并可取消；上传后复用现有蒙版画布、模型选择、生成/取消、按住对比。
- 导入位置支持选择媒体库、输入相对文件夹（空字符串为库根）、浏览已有文件夹、编辑文件名；导入前再次确认，成功或 `pending` 都有明确结果，可打开目标文件夹或再处理一张。
- 上传使用 XHR 和共享路径/响应契约，作业、取消、导入使用类型化 JSON 接口。
- mock 用于界面联调，不代表真实模型输出；真实模型与写盘能力由运行环境决定。
- 查看器修复编辑右上角重复的“完成”已移除；退出编辑使用左上角关闭按钮或 Esc，结果工具栏的“完成”保留。

## 持久化与恢复

上传先登记再流式写入缓存，按管理员用户隔离；中断或过期的暂存由后台清理。导入使用 SQLite 认领、私有目录和不覆盖的硬链接发布；请求编号重试沿用已预留的目标名称。索引未完成的已确认导入由后台重试。Linux 使用目录句柄固定路径；目录或文件身份变化时返回 `OPERATION_PARTIAL` 并保留待核验记录。身份不足以证明安全的历史暂存不会自动删除；运行账户须独占这些 0700 暂存目录，其他同 UID 程序不得修改目录内容。目标名称在预留后被外部程序抢占时，操作进入待核验状态，保留暂存与结果并停止自动重试；问题解决后可在当前页面沿用原操作编号重试，刷新页面后尚无放弃或恢复入口。单个 API 实例最多同时转码两个导入；多 API 实例不应视为资源全局硬隔离。
